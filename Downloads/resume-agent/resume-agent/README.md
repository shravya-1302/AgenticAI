# Autonomous Resume & Application Agent (Tech Zephyr 4.0 — PS11)

Paste or upload your **real resume** and a **real job description**. The
agent tailors a resume using only evidence it can find in your actual
resume text, checks its own draft against two independent tools, and
**replans when the check fails** — the core "agentic" loop the hackathon
rubric is scoring for.

```
DRAFT → RENDER (PDF) → EVALUATE (coverage score + factual check) → DECIDE
                              ↑                                       |
                              └── grow evidence pool / redraft ───────┘
                                                                       ↓
                                                        READY  or  ESCALATED
                                                     (with an honest gap report)
```

## Important: this uses YOUR real data, and never invents anything

- It never fabricates a skill, project, or achievement you didn't already
  write. If your resume has zero evidence for a JD requirement (e.g. the
  JD wants Python and you've never mentioned Python), the agent will not
  pretend you have it — it will **escalate** and tell you exactly which
  requirements have no supporting evidence, so you can decide what to do
  (add real experience, or note that it isn't actually required).
- Every bullet in the tailored draft is copied verbatim from a line in
  your resume — nothing is paraphrased or generated by an LLM. This keeps
  the tool 100% traceable: you can always see exactly which original line
  became which bullet (shown as `[ev4]`-style tags in the UI).


## How the loop actually behaves

1. **Parse** — the JD is scanned for known skill/requirement terms (a
   ~120-term vocabulary spanning tech, business, and general professional
   skills). Your resume is parsed into structured sections (summary,
   skills, experience, projects, education, etc.) and each experience/
   project bullet is tagged with whichever of those same terms it or its
   parent job/project title contains.
2. **Draft** — evidence is ranked best-first by: (1) how many JD
   requirements it covers, (2) whether it has a quantified metric (a %, a
   dollar figure, a time saved) — a keyword-only bullet never displaces a
   bullet with a real measurable result, and (3) real work experience
   ranked above personal projects on ties. The agent then fills a
   **one-page character budget** (`MAX_BULLET_CHARS` in `agent.py`,
   default ~1600 chars of bullet content) with the best-ranked bullets it
   can fit — it will not blow past one page even if that leaves some
   requirements uncovered.
3. **Evaluate** — three things are checked: coverage score, a
   quantified-impact ratio (share of included bullets carrying a real
   number), and factual-consistency (do bullets trace to real evidence).
4. **Decide**:
   - Score passes threshold → **ready**.
   - Page budget reached before hitting the threshold → **ready anyway**,
     with a note listing exactly which requirements were traded off to
     keep it to one page (length wins over chasing every last keyword).
   - Genuinely no evidence anywhere for a requirement (not a length issue,
     an actual gap) → **escalate**, naming exactly which requirements have
     no support in your resume.

## Running it on your desktop

### 1. Prerequisites
- Python 3.10+

### 2. Set up a virtual environment

```bash
unzip resume-agent.zip
cd resume-agent
python3 -m venv venv
source venv/bin/activate        # on Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Start the server

```bash
uvicorn backend.main:app --reload --port 8000
```

### 4. Open the app

Go to **http://127.0.0.1:8000**.

1. Paste your resume text into the left box, **or** choose a `.pdf`,
   `.docx`, or `.txt` file below it.
2. Paste the job description into the right box, **or** upload a file.
3. Click **"Start session"**.
4. Click **"Run next iteration"** to step through the loop one decision at
   a time (best for narrating a demo), or **"Run to completion"** to let it
   finish.
5. Once status is `ready`, click **"Download tailored resume PDF"**.

If status becomes `escalated`, check the "Change / replanning / escalation
log" card — it'll tell you exactly which requirements had no supporting
evidence in your resume.

### 5. Using the raw API directly (optional)

```bash
# Start a session (file upload)
curl -X POST http://127.0.0.1:8000/session/start \
  -F "resume_file=@/path/to/resume.pdf" \
  -F "jd_file=@/path/to/job_description.txt"

# ...or with pasted text instead of files:
curl -X POST http://127.0.0.1:8000/session/start \
  -F "resume_text=Your resume text..." \
  -F "jd_text=The job description text..."

# Step the agent forward (repeat until status is "ready" or "escalated")
curl -X POST http://127.0.0.1:8000/session/<SESSION_ID>/step

# Inspect full state at any point
curl http://127.0.0.1:8000/session/<SESSION_ID>/state

# Download the current best resume as PDF
curl -o resume.pdf http://127.0.0.1:8000/session/<SESSION_ID>/resume.pdf
```

## Known limitations (good things to mention as "future work" to judges)

- **Vocabulary-based matching, not semantic understanding.** The JD parser
  only recognizes terms in its fixed skill vocabulary (`SKILL_VOCAB` in
  `tools.py`). A JD saying "automated testing" won't match a resume that
  only says "unit tests" unless both exact terms are in the vocabulary —
  worth extending the vocab list or swapping in an LLM-based matcher for
  more flexible language understanding.
- **Line-based evidence, not semantic bullets.** Each resume line becomes
  one evidence item. A resume with unusual formatting (e.g. bullets split
  across multiple lines) may extract slightly oddly — worth adding a
  smarter bullet-boundary detector.
- **No company/role research step yet** — the problem statement suggests
  researching the target company/role; that would be a good next tool to
  add (e.g. a web-search call).
- **In-memory sessions** — restarting the server clears all sessions;
  fine for a demo, not for production.

Swapping in an LLM (e.g. via the Anthropic API) for the drafting step could
produce more natural-sounding bullets, but the current rule-based approach
was chosen deliberately: it's fully deterministic, needs no API key or
internet access, and every claim is provably traceable to your own words —
useful properties for a hackathon demo judges can trust and reproduce.
